# DeepSeek：成都校区本科新生资料采集

状态：用户已在独立 DeepSeek 会话中安排采集。本目录保留交付契约，不代表该会话的实时进度；
此工作区尚无该批新生候选的采集成功或发布记录。

目标：让新生快速找到线上官方入口或线下地点。依次完成下表；每项有可读证据或明确缺口后再进入下一项。

| 优先级 | 事项 | 必须查清 |
| --- | --- | --- |
| P0 | 2026本科迎新与报到 | 迎新入口、线上预报到、现场日期/地点/材料，成都与宜宾分开 |
| P0 | 统一账号和校园网 | 激活、登录、上网入口；小程序准确名称和进入路径 |
| P0 | 缴费和校园卡 | 官方缴费渠道、充值/挂失入口、补卡地点；区分余额与工本费 |
| P0 | 宿舍入住、报修、购电 | 入住地点、学生公寓报修、照明/空调购电；排除家属区渠道 |
| P0 | 新生常去地点 | 校门、教学楼、图书馆、食堂、宿舍园区、校医院、体育场馆名称/别名/地址说明 |
| P1 | 图书馆和体育设施 | 常规开放、假期例外、预约入口、使用条件 |
| P1 | 交通和第一学期 | 官方到校交通/校门、校内交通、校历、选课入口、军训和迎新活动 |

## 执行与交付

1. 阅读项目 `AGENTS.md` 和 `docs/KNOWLEDGE_GOVERNANCE.zh-CN.md`；先与现有来源按规范URL比对，复用已有来源，不堆重复网页。
2. 只采集公开官方内容。搜索用于发现来源，正文与附件用于事实核对；不登录个人账号。保存完整正文和原始供应商响应，PDF/图片保留原件；记录采集方法、日期与SHA-256。
3. 在本目录写 `items.json`（事项清单）、`raw/`（原件）、`evidence-index.json`（文件/URL/哈希）、`CONFLICTS.md` 和 `GAPS.md`。所有事项保持候选状态，不自行生成审批记录。
4. 每项填写 `item_id`、`topic`、`question_examples`、`online_entries`、`offline_places`、`conditions`、`campuses`、`audiences`、`academic_year`、`published_on`、`valid_from`、`valid_until`、`evidence_refs` 和 `status`。每个入口标明直接办理/平台/指南；每个证据定位到原件文件和具体段落或页码。
5. 不明字段填null或空数组并在GAPS中说明。2026报到、军训和迎新通知保留明确年份；不当作当前开放，不推算2027。校区、学院、人群、例外、脚注和表头须保留。
6. 同一问题出现冲突时，在CONFLICTS同时保留两边原文及适用范围。没有明确替代/废止依据，不宣布旧资料失效。失败响应单独登记，不当作有效资料。
7. 检查每个P0事项有证据或缺口；检查所有证据文件哈希、入口指向、范围和时效。最后交付逐项覆盖表、有效来源数、失败数、冲突和缺口，不以文件数量替代质量结论。

原文可用于指导坐标核验，但不生成经纬度、室内路线或实时营业承诺。应用代码、地图数据、当前版本、向量索引和发布由Codex集成；本任务只写本目录，不修改其他工作区成果。

本轮不扩教师名录、更多学院奖学金或泛新闻。线上办理给入口，线下办理给地点；必要条件保留，长步骤供用户按需查看。无需录制视频。
