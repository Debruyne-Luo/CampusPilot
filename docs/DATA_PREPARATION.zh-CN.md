# 资料准备：可以边开发边补

当前 Dify 是 RAG：检索资料后，把相关内容交给模型生成回答。现有三事务摘要库验证了这条链路，不代表全校知识或最新政策。政策说明用 RAG；精确部门/地点用结构化目录；路线用 GIS；登录和实际办理属于另外的集成能力。

## 谁准备什么

| 材料 | 我可以完成 | 需要你补充 | 最少保留 |
| --- | --- | --- | --- |
| 公开办事指南、通知、FAQ | 查官方网页/PDF、整理、去重、记录来源 | 指定优先事项、指出实际流程差异 | 标题、官方链接/原文件、日期、人群/学年/校区 |
| 登录后才能看到的指南 | 整理你提供且允许用于项目的内容 | 导出允许使用且去掉个人信息的指南内容；无需账号密码 | 系统名、页面标题、日期、范围、使用限制 |
| 办事地点和开放时间 | 整理公开信息、建立字段关联 | 缺失时确认校区、楼栋、房间/窗口、入口和开放时段 | 来源、核实日期、例外或变化 |
| GIS 地图与路线 | 评估地图方案、建地点表、接路线与界面 | 确认目标校区、关键入口、通行限制；有公开校图可提供 | 地图来源/使用条件；坐标若已有，需附坐标系和来源 |
| 演示任务 | 设计演示链路 | 最希望评委看到的 3–5 个任务 | 用户问题、预期完成到哪一步 |

不需要先收集完整学校、购买地图服务或手工标注全部坐标。校园地图图片可帮助识别地点，但不能直接证明通行条件或计算真实路线。不要收集学生证件资料、密码、验证码或个人缴费记录。

## 发给我的最小模板

原始资料即可，不必先整理成标准答案。未知项留空：

```text
事项名称：
适用人群、校区、学年或有效日期：
官方链接或允许使用的文件：
负责部门：
办理步骤和官方入口：
楼栋/房间/入口与开放时间：
材料、费用、限制：
来源与取得/核实日期：
仍不确定的地方：
```

整理、分段、入库和接口格式由开发处理。新资料先记 needs_review，人工复核后再决定是否发布为已核验事实。

## 目前最有用的补充

1. 校园卡相关自助设备的确切位置和开放时间。
2. 研究生证明打印设备位置，以及 2023 试运行规则目前是否仍适用。
3. 票据通知未说明的渠道/异常处理信息，需官方依据。
4. 优先展示的校区和 3–5 个地点，后续据此做小范围 GIS 演示。

这些材料无需一次交齐。接口、界面和任务编排不必等待资料齐全才开始。
