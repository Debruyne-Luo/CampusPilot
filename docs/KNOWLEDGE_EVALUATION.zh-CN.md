# 知识库分层评测与发布审查

2026-10-17 用户已授权实施知识库重采计划。评测与答题链路分开；运行本页默认命令不初始化模型、嵌入服务或 Firecrawl，不产生外部调用。

## 新评测契约

`campuspilot.knowledge_evaluation` 提供严格的 `QualityCase`、`EvidenceAnchor`、`Observation`、`AnswerReview` 和 `evaluate_quality`。`evaluation/knowledge-quality-20261017/` 保存 120 个新问题、构建来源与清单：60 个开发、60 个保留，六类各 20，每类在两个集合中各 10。24 个来源/事项组跨集合隔离，另检查来源 ID、URL 和相同问题泄漏；语义近似仍需独立审查。

每条证据有原文引句、必要事实、来源 URL/ID、版本哈希、定位与基线知识版本。片段 ID 只作映射；同来源重新分块后，检索按引句匹配。`raw_body` / `raw_attachment` 哈希对应已保存原件；`snapshot_extract` 是固定快照中该来源及其摘录的哈希，不能冒充原始网页。构建器从固定 JSON 记录计算旧摘录哈希，新增模型默认字段不会改变其身份。

摘取核对与金标核对分开：2026-10-17 独立代理在未读取保留集观测的条件下审查全部 120 题，阅读固定快照的 24 个来源、相关完整正文以及账号激活、网络报修、借户口本和心理预约原图。38 题具有完整原件和全部锚绑定，标记 `source_checked`；82 题因原件缺失、附件解释尚未绑定或冲突另一方原件缺失继续 `draft`。168 个锚中 54 个已审查绑定，114 个保留草稿。`source_checked` 不代表人工复核、政策现时有效或现场验证。

构建器只重放逐题写明的必要事实、下一步和明确授权的来源核对清单；不会仅凭包含引句就认证金标。每题修正前后契约、哈希、修正理由、原件和剩余缺口见 [独立金标审查](research/knowledge-gold-review-20261017.md)。原审查套件哈希 `2314c0a4…` 已被修正版本 `571902a1…` 替换；旧观测的题目绑定失效，不能直接复用。

`answer`、`partial`、`clarify`、`refuse`、`unlabeled` 为明确标签。缺少证据标签不等于应当拒答。旧脚本已将 `refusal_correct` 改为 `no_gold_empty_retrieval`，将 `citation_precision` / `citation_hit_rate` 改为展示片段与金标的重合指标；旧报告文件保留为历史记录，不重写其原始结果。

## 运行与审查

先运行开发集；候选路径需对应根任务生成的快照。

```powershell
.venv/Scripts/python.exe -X utf8 scripts/evaluate_knowledge_quality.py --snapshot data/cdut/rag/versions/kb-229ee34eba99ef34/snapshot.json --output output/knowledge-quality-20261017/baseline-development.json
.venv/Scripts/python.exe -X utf8 scripts/evaluate_knowledge_quality.py --snapshot data/cdut/rag/candidates/rebuild-20261017/snapshot.json --output output/knowledge-quality-20261017/candidate-development.json
```

默认只测 `development`；`--split holdout` 或 `--split all` 只用于冻结后的最终比较，不据保留集结果调参。历史基线和候选各报告一次最终结果。原文锚审计会检查路径限制、文件哈希及引句；失败即终止。默认检索为离线 BM25，只证明词法路径，不构成 BGE-M3/RRF 或端到端质量验收。

报告同时输出 `.observations.jsonl` 与 `.review-template.jsonl`。如果已有公开固定题的真实答题观测，传入 `--observations`；逐题对照原文完成审查后再传入 `--reviews`。没有回答文本的纯检索观测始终 `unassessed`，不能填成回答通过。审查输入绑定完整观测哈希，观测又绑定题目契约哈希与知识版本；改答案、问题或版本后，旧审查不能复用。

检索分别报告证据 Recall@5、MRR@20、完整证据集合覆盖、错误适用范围命中和展示摘录重合。`retrieval_required` 区分运行时必须召回的证据与只供离线审查的历史锚：当前 88 题要求现行检索，32 题为历史、已停用来源或旧 POP3 设置边界，不要求当前检索返回被排除的旧规则。召回类指标仅计需要检索的场景，32 题仍须实际回答和逐题行为审查，不能跳过验收。未知校区/人群不作为已证明错误，仍是数据缺口。默认当前问答中的历史来源按不适用命中审计；该计数本身不等于答案已犯事实错误。

回答审查单独记录事实正确、必要事实完整、引用支持、引用覆盖、行为正确、可执行下一步和金额/期限/资格/地点/步骤严重错误。答案与应澄清/拒答场景分别计数。审核备注必须说明原文支持，不能只填模型总分。

发布门槛同时要求：120 题结构与拆分完整、原文锚审计完成、全部金标完成来源核对、60 个保留场景实际答题并逐条审查、至少 54 个整体通过、无严重错误，以及实际完成相关回归。`--required-checks-passed` 只能在相关回归实际通过后使用；`--require-gate` 在未达标时退出 2，供发布流水线阻断。缺资源或未复核项必须保持阻断，不能从检索指标推导回答验收。

## 当前证据与局限

独立审查修正了宜宾场景却固定成都输入、将2026届毕业贷款通知直接用于当下在校生、要求当前检索返回历史安排、把采集注记当作原文、复学缺少医院复查、农信付款漏掉进入缴费页等问题。这些属于金标正确性修正，未依据检索得分调参。旧套件开发诊断只保留作历史记录；修正套件须重新运行并以报告中的完整哈希为准。

独立金标审查没有调用模型、网络或外部嵌入，也未读取保留集结果。答案、引用事实支持和 54/60 发布验收须由实际观测与审查报告证明；保留集不用于调参。部分旧来源只有摘要，格式题并未全部取得 PDF/图片原件，82 个金标仍阻止完整发布验收。
