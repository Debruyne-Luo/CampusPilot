## 日常规则

- `main` 为唯一长期主线，保存已审核的完整项目。无需额外长期 `develop` 或 `handoff` 分支。
- 从最新 `main` 建短期 `feat/...`、`fix/...`、`docs/...` 或 `chore/...` 分支；一项工作一个 PR，
  通常以 `main` 为目标。必须堆叠 PR 时，在前置 PR 合入后及时调整后续目标分支。
- PR 合入后检查无独有改动、无仍依赖它的开放 PR，再删除远端分支。
- `v0.1.0` 固定已上线的 `31ed5bb0264d927c7918046b66b2947c013e8205`。
  发布标签指向实际部署代码，创建后不移动；新增文档/评测不代表网站已重新部署。
- 下一次发布记录提交 SHA、发布包、知识快照、运行配置及验证结果，按实际发布更新
  [线上基线](LIVE_BASELINE.zh-CN.md)。用户的合并授权不自动代表部署或独立验收通过。
- 合并仍须遵循用户授权和项目审核流程。本次用户明确批准执行上述整理及合并，是本次操作依据。
