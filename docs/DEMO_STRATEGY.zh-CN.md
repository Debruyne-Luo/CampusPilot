# 比赛演示：把校园信息变成下一步行动

本轮展示定位为**PROPOSED**：先服务对校园不熟的新生，以及偶尔办理证明、补卡等事务
的在校学生。现有证明资料限定研究生；不能对本科生套用。教师与行政人员可作为后续扩展。

痛点是信息分散在官网、学院通知和公众号：查到了文章仍不清楚是否适用、需做什么、
去哪儿。CampusPilot把适用资料、办理步骤、官方入口和地点路线接起来。地图覆盖是基础；
展示重点是用户从“要办什么”走到“下一步能做什么”。首页已体现这条主张，双模式让操作直观。

## 90秒可复现演示

1. 前10秒：手机打开“校园地图 / 事务助手”，说明“少翻几篇通知，少跑一趟冤枉路”。
2. 10–35秒：询问“校园卡需要补办，应该怎么做？”展示短答与完整步骤，再点官方依据。
   补卡设备位置目前未知，清楚保留文字指导；不拿食堂坐标当设备坐标。
3. 35–60秒：查“借书”或“校园网”，展示已收录官方指南、适用人群、发布日期及原文。
   “校庆”可演示报名截止/已结束判断；不要把旧活动包装成本周活动。
4. 60–90秒：切地图搜“攻坚楼”，展示原20条目录外的真实高德地点；或用东区图书馆到
   珙桐餐厅的真实路线，显示距离、分步与引导入口。桌面演示用目录起点，真机在校园测试
   后展示持续GPS。模拟定位必须明确标为测试，不能当真实导航视频。

## 能用证据支撑的优势

| 展示点 | 用户价值 | 当前证据与边界 |
| --- | --- | --- |
| 需求→步骤→官方入口→地点 | 减少在文章、问答和地图之间来回切换 | 4项事务、教师/地点卡片、原对话返回 |
| 根据对象/有效期选择资料 | 防止套错本科/研究生规则，误读过期通知 | 6条官方资料及类型/时间/人群筛选；覆盖仍有限 |
| 确定的业务ID关联地图 | 保留房号与办事上下文，缺失位置也能继续 | 业务ID由实际查询返回；模型文字不能造坐标 |
| 超出目录的地点发现与站内引导 | 查询后可直接出发 | 高德热点、周边POI、真实步行路径；后台/室内导航未交付 |

以上组合可以作为创新表达，不能宣称通用RAG本身是独创、全校数据全覆盖或能代替学校办事。
公众号信息后续通过来源归属、日期抽取、导入和版本更新接入同一事项流程；当前有导入
合同与Dify语料导出，尚无自动采集所有公众号文章的能力。

下一步用3–5名同学完成同一项任务，记录首次找到正确步骤/入口的用时、错误人群/过期
信息使用率、地图抵达与返回对话情况；有实测再展示节省时间比例，不编造提升数据。
