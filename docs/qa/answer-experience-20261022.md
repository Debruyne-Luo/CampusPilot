# 回答阅读与办理清单核验 · 2026-10-22

本轮处理正式入口截图中的四项反馈：回答重点不清、处理过程抢占正文之前的位置、
学生页面多余的 Jev 决策记录，以及第一次办理回答缺少加入清单按钮。
这是实施与切换前核验记录；生产身份、最终 CI 和真实回答复跑结果另见发布附件，
不能沿用上一版的 57/60 作为本次提示词的验收结果。

## 行为调整

- 答案按短段展示，安全渲染简短加粗标签，保留全部正文；不以截断、隐藏警告或丢弃金额来缩短。
  有结构化流程时，模型收到页面已有详细步骤的明确上下文；没有流程时明确告知不存在该控件。
  此上下文在模型追加工具查询后重新计算，正文概括下一步、渠道及关键提醒。
  快捷目录回答同样分段突出入口与限制，材料留在折叠区。模型输出仍须通过 JSON、引用和事实校验。
- “查看办理步骤”集中展示已有的材料、需准备的信息、条件、详细操作、费用和来源限制，默认折叠。
  移除重复的“查看材料与步骤”追问按钮；展开已有内容不再发起一次问答。
- 学生回答不再渲染“执行记录 · Jev 决策”。后端决策功能、已有事件及维护端实验记录接口保留。
- 一次回答匹配一个有步骤的正式 procedure 时，直接显示“＋ 加入办理清单”。
  保存仅复制公开结构化资料，不从模型正文生成材料，不保存聊天或个人定位，也不增加模型调用。
  显式清单工具拒绝、失败、多个事项、guide/directory 和澄清回答不会借此获得保存入口。
  已加入时显示“已加入 · 查看清单”，原 v1 存储与勾选进度兼容。
- 完成后的“查看处理过程”位于该轮所有回答、地点和来源之后；断流也收束为已结束的折叠记录。
  回答完成时优先显示答案开头；用户正在回看内容或打开清单时不抢走阅读位置与视图。

## 验证

新增回归在修复前失败，覆盖首次保存、歧义与拒绝边界、正文安全分段、完整折叠资料、
移除学生决策记录，以及模型只在页面实际有结构化步骤时收到对应展示上下文。
手机“最终自动滚到底而遮住标题”也先在 390 像素浏览器中复现，再用相同检查验证修复。

本地针对 Python 回归 75 项通过；Node 105 项通过；Ruff 通过，mypy 166 个源码文件通过。
Starlette/httpx 测试客户端的既有弃用提示保留。Linux 全量及最终提交身份由 GitHub Checks 记录。

`tests/browser_answer_flow.js` 使用明确标注 SYNTHETIC 的流式数据和隔离存储，
在 1440、390、320 像素宽度核对答案开头可见、处理过程置底、默认折叠、清单按钮 44px 高且
无横向溢出、首次保存、刷新后勾选进度，以及流中断后无永久“进行中”。所有视口页面异常为 0。
`browser_pine_states.js` 的上传重试/移除、保存/刷新/新对话、完成撤销、网络恢复和 HTML 惰性渲染通过；
`browser_desktop_streaming.js` 的增量内容、下一条草稿、手动阅读位置及清单视图保留通过。

真实公共问题小样本另行检查校园卡补办、20 元余额与工本费区别、快捷地点、网络报修指南等。
模型段落长度是生成指引，必要的年份、校区、金额、例外和未知项较多时仍可能超过默认字数；
没有为满足长度删去校验或自动裁剪。小样本不能替代固定 60 题复跑，也不能证明全部真实问题正确。

本轮未改知识指针、工具权限、服务入口、地图模型或浏览器存储格式。
真机微信/Safari、实际定位与低端设备仍需设备验收；桌面模拟不是这些项目的通过证据。
