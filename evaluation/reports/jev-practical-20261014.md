# Jev 真实调用对照：当前整轮拦截不宜默认开启

更新：下述 10 月 14 日实验针对修正前接法；10 月 15 日已修复部分答案被整轮隐藏的问题。
后续验证见本文末尾，不能将旧失败数字用于修正后版本。

**2026-10-14，CONFIRMED（本次实验观测）：当前接法降低了部分回答的完成率。**
Jev API 可以正常调用，能识别“资料相关但不足以完整回答”；然而应用将这个判断用于整轮拦截，
把本来可以回答的内容也一起隐藏了。这不证明 Jev 模型在其他接法中没有价值。

  所有后端 Python 文件哈希保存在 [identity.json](../jev-practical-20261014/identity.json)。不能简称为原始提交的评测。
- 固定知识 `kb-229ee34eba99ef34`，322 个片段；snapshot SHA256 为
  `23515fe696a33b361e078d6bb5bf67df43443c4663ce4d510100fb20c040b7f5`，manifest SHA256 为
  `c64400e98e66446b9e13610b001b7206d18a575a0f4137c17d35d8bc671e2dfa`。

  生成上限 1500 tokens，混合检索，Cloudflare BGE-M3 1024 维，固定 30 个问题向量。
- 每题新会话；三组顺序轮换，并发上限 2；固定快照，关闭联网搜索，专门观察检索和生成前判断。

## 结果

检查答复正文是否完成被问到的、可由资料支持的部分，不能以 `success` 字段代替正确性。
只列来源、要求用户重新提问、或整轮澄清，不算已完成部分回答。附加描述的瑕疵另列。

| 指标 | A：Jev 关闭 | B：本地 block | D：Jev 开启 |
| --- | ---: | ---: | ---: |
| 完整证据题：核心问题完成 | 7/10 | 6/10 | 6/10 |
| 部分证据题：已知部分完成且未知明确 | 6/10 | 7/10 | 2/10 |
| 无证据题：没有断言被问到的未知事实 | 10/10 | 10/10 | 10/10 |
| 部分证据题：整轮要求澄清 | 0/10 | 0/10 | 6/10 |
| 答复 wall-clock 中位数 | 2.99 秒 | 2.93 秒 | 3.34 秒 |
| 答复 wall-clock P95 | 3.76 秒 | 3.66 秒 | 4.48 秒 |
| 有 usage 的生成调用费用估算 | $0.018790 | $0.017225 | $0.008818 |

这是每题单次调用的小样本。生成存在随机性，完整证据题的组间小差别不能直接归因为 Jev。
P95 为 30 次 wall-clock 的 nearest-rank 统计，包含解释、检索、判断和生成，不是首字延迟。
D 的生成费用下降也包含少生成完整答案的影响，不能据此认定性价比提高。

Jev 正式组 29 次调用均有有效响应/usage，无超时或供应商错误；18 次可应用，11 次因既有置信度
规则进入 `unsure`。判断本身的延迟中位数为 **0.77 秒**，输入 token 合计对应 **$0.002492**
的估算费用。当前主要问题是决策用途，而不是 API 可用性或这轮费用。

正式 90 次答复共 170 次生成请求，均返回 HTTP 200；生成合计估算 **$0.044833**，加正式 Jev 为
**$0.047326**，不含 embedding。计价依据为
[DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)及
[Jev 价格](https://openrouter.ai/typesafe/jev-1.13)。这些是由 usage 和价格计算的估算，不是账单确认。
共享实验预算上限 $1；总账占用 **$0.133824**，还包含前置探测、无 usage 的 embedding 保守上限，
以及旧生成凭据 HTTP 401 的保守预留；不能把总账占用当成实际支出。401 试跑未计入质量结果。

## 可以直接检查的失败样例

| 题号 | 问题 | A、B 的答复 | D 的答复及判断 |
| --- | --- | --- | --- |
| P02 | 本科生能借多少本，最多续借几次？ | 40 本；续借次数未知 | 整轮澄清；Jev `clarify`，sufficient=0.34 |
| P04 | 第一次借书怎么做，丢书赔多少钱？ | 给出借书步骤；赔偿金额未知 | 整轮澄清；已知借书步骤也被隐藏 |
| P09 | 成绩复核在哪申请，保证几天出结果？ | 给出申请入口及期限差异；出结果时间未知 | 整轮澄清；申请方式也被隐藏 |
| P10 | 2023 通知中证明线上费用/次数，线下免费几份？ | 线上免费、每日一次、下载不限；线下免费份数未知 | 整轮澄清；历史适用范围内的有效答案也被隐藏 |

这四题的 D 均在生成前被应用策略截断，不是答复生成措辞不同造成的差异。
`agent/executor.py` 的 `_with_jev` 只以 `ev.has_structured()` 保留目录/清单证据，
纯文档中的部分证据没有同样的保护。因此 Jev 判断“整个问题不足”时，应用返回同一条泛化澄清文本。
澄清要求补身份或时间，但这些信息本身不能补出未收录的续借次数、赔偿金额或免费份数。

无证据题 N01、N02 中，A/B 返回邮箱激活资料兜底，D 阻止了不相关来源展示；这是一项局部改善。
但 A/B 也没有编造容量或改名规则。本轮没有观察到 D 减少“被问未知事实的无依据断言”。
N04、N06、N07 中，A/B 已明确说明未知，D 换成泛化澄清，拒答次数增加并不表示答案更好。

另外，两项问题不能靠启用 Jev 解决：

- F01、F02、F07 三组均有证据却降级为 `answer_validation`，只展示来源；
  F06、P03、P06 也出现该降级。供应商 HTTP 200 不等于应用答复校验通过，根因需用这些公开失败题复现。
- B/F05 在正确借书步骤后追加“带上本人校园卡”，本轮检索证据没有这项要求；
  该题核心完成，但附加指导缺依据，所以 B 的严格全答复有据完成为 5/10。
  A/B 的 P05 还把未在本轮检索到的信息说成全库未收录；这种范围扩大需单独修正。

## 下一步

**PROPOSED：当前不默认启用 Jev 的整轮拦截。** 本地 `block` 的规则也只是部分相关性检查，
例如 N01/P02 仍被判 `grounded`，不能代替事实充分性判断。

1. 优先复现并修复“有证据却 `answer_validation`”的原始失败；保留验证约束，用公开题补回归。
2. 让文档证据也能保留已证实部分。若继续试 Jev，先限定为证据排序或子问题判断，
   避免以全题充分性直接否决全部回答；这些替代接法的收益尚未验证。
3. 修正后重跑这组题用于回归，再用未参与修正的留出题比较无依据断言、错误拒答、部分完成、延迟与费用。
   只有净收益明确再考虑改变默认开关。

## 2026-10-15：部分答案修正与真实回归

**CONFIRMED（本地实现及本次回归）**：已修复整题不足时隐藏仍有用文档的接法。
没有更改 Jev 默认开关、校准阈值、公共 API 或线上配置。

具体变更：

- 生成前、模型追加检索和联网前都区分“无保留片段”与“整题未答全”。仍有保留片段或目录事实时，
  生成已有依据的部分并明确未知；不再仅因整题 `clarify/insufficient` 隐藏全部答案。
- 联网超时、预算耗尽、无正文或新网页未获采纳时，仍生成本地答案并注明补证限制。
  未采纳的官方网页和第三方网页均不能进入生成材料或可引用 ID；无本地依据时仍不给无据成功答复。
- 显式联网要求不被提前澄清吞掉。搜索带学校名称和 `site:cdut.edu.cn`，保留十秒期限、SSRF 和预算边界。
- 已检索办事入口按钮 ID 可映射回其来源；未知 ID 仍被拒绝。生成材料遮去 URL/域名但保留事实与引用 ID，
  完整链接仍由程序展示。时间校验支持“下午 2:30–6:00”和正文粘连的编号，不放过不同时间或模糊跨夜时段。
- 提示词明确“未收录”不等于“不存在/不允许”，针对上一轮 N09 把未知通宵安排写成否定的失败。

最终回归固定同一知识快照、当前工作区文件哈希、模型和配置，选择 F01/F02/F07、
N01/N02/N09、P02/P04/P09/P10 共 **10 题 × 3 组 = 30 次真实答复**：
关闭 Jev、开启修正后的 Jev、开启修正后的 Jev＋真实 DeepSeek 搜索。
这次使用当前运行代码，不再借助上一轮的实验 `RankingOnly` 子类。
这是用于修正的开发回归题，不是留出集；由 Codex 按冻结来源核对正文，没有独立人工标签。

观察结果：

- 三组均完成 **3/3** 道完整证据题，保留 **4/4** 道部分答案，对 **3/3** 个被问未知事实保持未确认。
  只表示这些核心问题的完成与未知项保留，不代表整份答复每项附加指导都已验证。
- Jev＋联网实际补证 **4 次**，全部返回 `limited/no_readable_page_body`，取得可采用的官方正文 **0 份**。
  N01、N02、P04、P09 仍保留本地答复并告知网页限制；P04/P09 没再退化为来源标题兜底。
- 答复 wall-clock 中位数分别为 **4.39 / 4.85 / 5.15 秒**。每组仅 10 次，P95 分别为
  **22.54 / 23.62 / 15.20 秒**，含供应商重试长尾，不是首字延迟或稳定性能排序。
- 该次共享 $1 上限账本占用 **$0.034301**：有 usage 的生成估算 $0.015011、
  Jev $0.002071、原生搜索按保守配置估算 $0.006971，另有 4 次生成请求用量未知的
  $0.010249 保守预留。不得将账本占用或配置估算当作账单确认。
  [DeepSeek 价格](https://api-docs.deepseek.com/quick_start/pricing/)和
  [Jev 价格](https://openrouter.ai/typesafe/jev-1.13)于 10 月 15 日复核。

本机默认 DNS 将学校域名解析到测试网段，正文读取器按约束拒绝。正式联网回归使用显式公网 DoH
解析器隔离这一环境因素，并仍执行地址校验、连接固定和重定向检查；该解析器没有写入生产配置。
公网解析后的学校页面仍未取得正文，不能凭这些结果断言线上部署环境也同样失败。
没有绕过读取保护、将搜索摘要视为正文，或自动开启未确认的付费/免费备用账户。

**PROPOSED**：保持 Jev 和联网的默认开关不变。Jev 修正后的运行链路可用，但本次与关闭组结果持平，
